# SeumSteamOpt

Плагин, сокращающий количество обращений к Steam API в **SEUM: Speedrunners from Hell**.

Работает через Harmony-патчи поверх оригинальной `Assembly-CSharp.dll` —
подменять файлы игры не нужно.

## Принцип

Плагин ничего не добавляет и не убирает из функциональности игры. Все патчи
делают ровно одно из двух:

* отвечают на вопрос к Steam тем ответом, который игра уже получила и который
  не мог измениться;
* не дают игре перезапрашивать то же самое по таймеру, который не смотрит, могло
  ли что-то поменяться.

Единственная настройка с наблюдаемым эффектом — `RefreshCooldownSeconds`: она
решает, насколько устаревшей разрешено быть таблице рекордов. Всё остальное
включено по умолчанию и невидимо для игрока.

## Что именно происходит в ванили

### 1. Каждое чтение таблицы рекордов — два запроса вместо одного

`SteamDownloadRequest.start()` вызывает `FindOrCreateLeaderboard`, чтобы
превратить имя вида `level12_v8` в хэндл `SteamLeaderboard_t`, ждёт колбэк и
только потом вызывает `DownloadLeaderboardEntries`. То же самое делает и
`SteamUploadRequest`. Хэндл стабилен в пределах процесса (Valve прямо
рекомендует его кэшировать), поэтому начиная со второго чтения доски поиск —
чистые накладные расходы.

### 2. Перезапрос идёт по слепому таймеру раз в 5 секунд

| Экран | Что перезапрашивается каждые 5 с |
|---|---|
| `SpeedrunSelector.performUpdate` | `refreshLeaderboards()` — 2 доски full-game + 14 зон × 2 (с пивом и без) = **30 досок**, то есть **90** `SteamDownloadRequest`, то есть **180** обращений к Steam. И так всё время, пока открыт экран выбора спидрана. |
| `GameManager.Update` | Доска текущего уровня (`refereshCounter`, сброс на 5 с) — 3 запроса, 6 обращений. Идёт весь забег, независимо от того, видна ли таблица. |
| `LevelSelector` | На каждую смену зоны — `refreshScoresForZone`, то есть 11 уровней × 3 = **33** запроса, 66 обращений. Таймера здесь нет, но зону можно крутить сколько угодно. |

Ни один из этих вызовов не проверяет, не летит ли ещё предыдущая пачка и не
пришли ли эти же данные секунду назад.

### 3. Имена игроков перечитываются каждый кадр

`LeaderboardsSteamBackend.update()` вызывается из `GameManager`,
`LevelSelector` и `SpeedrunSelector` **каждый кадр**. Для каждого скачанного
запроса он проходит по всем 15 строкам и на каждой зовёт
`SteamFriends.GetFriendPersonaName` **и** `SteamFriends.RequestUserInformation`
— и продолжает это делать, пока Steam не разрешит имена всех игроков на доске.
После обновления зоны в селекторе уровней в работе одновременно ~33 доски,
то есть до 495 строк — около **тысячи маршалящихся вызовов Steam за кадр**,
пока имена не подтянутся.

### 4. Ачивки перечитываются на каждый выстрел и прыжок

`SeumSteam.saveAchievement` сначала читает ачивку из Steam
(`GetAchievement`) и только потом решает, что делать нечего. Для одноразовых
событий это бесплатно, но `Fire666times` висит на каждом фаерболе, а
`Jump666times` — на каждом прыжке. После 666 выстрелов/прыжков это вызов в
Steam по несколько раз в секунду ради уже полученной ачивки.

### 5. Воркшоп опрашивает состояние карт раз в секунду

`Workshop.performUpdate` раз в секунду зовёт `SteamUGC.GetItemState` для
каждой подписанной карты, хотя состояние меняется только тогда, когда Steam
присылает колбэк установки/обновления/подписки.

## Патчи

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `CacheLeaderboardHandles` | `true` | Запоминает `имя доски → SteamLeaderboard_t`. При повторном чтении `start()` сразу идёт в `DownloadLeaderboardEntries`, минуя `FindOrCreateLeaderboard`. Хэндлы запоминаются и из download-, и из upload-пути. Убирает **половину** трафика таблиц рекордов после первого обращения к каждой доске. |
| `RefreshCooldownSeconds` | `30` | Минимальный интервал между двумя загрузками одной и той же доски. Блокирует `downloadScore`/`downloadScoreWorkshop`, то есть 3 запроса за раз. Ранее скачанные рекорды остаются на экране: `Leaderboard.requestTimestamp`/`responseTimestamp` в игре нигде не читаются, так что зависшего состояния «загрузка» не остаётся. `0` — ванильное поведение. |
| `CachePersonaNames` | `true` | Кэш `SteamID → имя`. Сбрасывается по колбэку `PersonaStateChange_t`, так что отображаемое имя остаётся корректным. Пустые ответы (Steam ещё не подтянул пользователя) держатся только до истечения интервала повтора — строка не может залипнуть пустой. |
| `UserInfoRequestInterval` | `0.25` | Столько секунд переиспользуется предыдущий ответ `RequestUserInformation` для того же SteamID. Ответ меняется только когда завершится начатая им загрузка, поэтому спрашивать 60 раз в секунду смысла нет. `0` — ванильное поведение. |
| `CacheUnlockedAchievements` | `true` | Подтверждённо разблокированная ачивка больше не запрашивается у Steam до конца сессии. Подтверждение читается у Steam, а не предполагается: `SetAchievement`/`StoreStats` могут не пройти в оффлайне, и закэшировать несостоявшуюся разблокировку означало бы молча отнять ачивку у игрока. |
| `ItemStateCacheSeconds` | `5` | Кэш `GetItemState` для воркшопа. Сбрасывается колбэками `ItemInstalled_t`, `RemoteStoragePublishedFileUpdated_t`, `…Subscribed_t`, `…Unsubscribed_t` — то есть ровно в тот момент, когда состояние действительно изменилось. `0` — ванильное поведение. |

### Диагностика

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `StatsLogInterval` | `0` | Период (в секундах) строки «сколько вызовов Steam сэкономлено» в `BepInEx/LogOutput.log`. `0` — только один раз, при выходе из игры. |
| `VerboseLogging` | `false` | Логировать применение каждого патча и каждый выученный хэндл доски. |

## Что остаётся нетронутым

* `SteamAPI.RunCallbacks()` в `SteamManager.Update` — обязательная покадровая
  прокачка колбэков, её трогать нельзя.
* Загрузка рекорда (`SteamUploadRequest`). После успешной загрузки игра сама
  добавляет три `SteamDownloadRequest` напрямую, минуя `downloadScore` — то
  есть **свой новый рекорд виден сразу**, кулдаун на него не действует.
* Скачивание реплеев, публикация карт в воркшоп, аватарки, оверлей Steam — всё
  это событийное, перезапросов там нет.
* `LeaderboardsBackend.isScoreCurrentUser` — уже закэширован в
  [SeumPerf](../SeumPerf/README.md) (`CacheSteamUserId`); дублировать не нужно.

## Порядок величин

Для экрана выбора спидрана, где ванильная нагрузка максимальна:

```
ваниль:                   90 запросов / 5 с  ×2 вызова  = 36 вызовов Steam в секунду
+ кэш хэндлов:            90 запросов / 5 с  ×1 вызов   = 18 вызовов в секунду
+ кулдаун 30 с:           90 запросов / 30 с ×1 вызов   =  3 вызова в секунду
```

Плюс покадровый цикл имён, который при 60 fps в вершине даёт около тысячи
вызовов за кадр и после кэширования сводится к обращениям к словарю.

Это арифметика по структуре вызовов, а не замер; фактическую экономию за
сессию показывает `StatsLogInterval` (строка `Steam calls avoided so far: …`).

## Совместимость

Патчи `SteamFriends.GetFriendPersonaName`, `SteamFriends.RequestUserInformation`
и `SteamUGC.GetItemState` ставятся на сам Steamworks.NET
(`Assembly-CSharp-firstpass.dll`), поэтому кэш работает и для остальных
плагинов репозитория, которые ходят в эти методы.

Каждый патч регистрируется отдельно: если игра переименует метод, отвалится
только этот патч, а не плагин целиком (в лог уйдёт `could not resolve …`).

## Конфигурация

Файл создаётся автоматически при первом запуске плагина:

```
<папка игры>\BepInEx\config\SeumSteamOpt.cfg
```

<summary>Пример конфига (SeumSteamOpt.cfg) со всеми параметрами</summary>

```ini
[01 - General]

## Общий выключатель. При false не применяется ни один патч.
Enabled = true

[02 - Leaderboards]

## Каждая загрузка лидерборда начинается с FindOrCreateLeaderboard, чтобы
## превратить имя доски в хэндл, хотя игра спрашивает одни и те же имена
## снова и снова, а хэндл не меняется, пока запущен процесс. Кэш убирает
## один поход в Steam из каждого чтения — половину трафика лидербордов
## после первого обращения к каждой доске.
CacheLeaderboardHandles = true

## Минимальный интервал между двумя загрузками одной и той же доски. Ваниль
## перезапрашивает по слепому таймеру раз в 5 секунд без учёта того, сколько
## досок это затрагивает: один экран выбора спидрана — 30 досок (90 запросов)
## каждые 5 секунд. Свой новый рекорд по-прежнему виден сразу — успешная
## загрузка рекорда скачивается напрямую, минуя этот кулдаун. 0 — ванильное
## поведение.
# Допустимые значения: 0-600
RefreshCooldownSeconds = 30

[03 - Friends]

## Пока в скачанном лидерборде остались неразрешённые игроки, игра каждый
## кадр спрашивает у Steam имя каждой строки — 15 имён на доску, а на экране
## выбора уровня одновременно открыты десятки досок. Имена кэшируются по
## Steam id и сбрасываются, когда Steam сообщает о смене профиля игрока.
CachePersonaNames = true

## Тот же цикл каждый кадр вызывает RequestUserInformation для каждой
## строки. Ответ меняется только когда Steam закончит подгружать
## пользователя, так что спрашивать 60 раз в секунду смысла нет — вот
## сколько секунд переиспользуется предыдущий ответ. 0 — ванильное
## поведение.
# Допустимые значения: 0-5
UserInfoRequestInterval = 0.25

[04 - Achievements]

## saveAchievement перед тем, как ничего не делать, сначала перечитывает
## ачивку у Steam. Два места вызова — на каждый выстрел и на каждый прыжок,
## так что после 666 выстрелов/прыжков это поход в Steam несколько раз в
## секунду ради уже разблокированной ачивки. Подтверждённые разблокировки
## запоминаются на сессию.
CacheUnlockedAchievements = true

[05 - Workshop]

## Экран воркшопа раз в секунду опрашивает GetItemState для каждой
## подписанной карты. Результат меняется только по колбэку Steam об
## установке/обновлении/подписке, и эти колбэки сразу сбрасывают кэш, так
## что опрашивать чаще — впустую. 0 — ванильное поведение.
# Допустимые значения: 0-60
ItemStateCacheSeconds = 5

[06 - Diagnostics]

## Период (в секундах) строки «сколько вызовов Steam сэкономлено» в логе.
## 0 — только один раз, при выходе из игры.
# Допустимые значения: 0-3600
StatsLogInterval = 0

## Логировать каждый применённый патч и каждый выученный хэндл доски.
VerboseLogging = false
```
