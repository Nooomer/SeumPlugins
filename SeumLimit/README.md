# SeumLimit

Плагин для **SEUM: Speedrunners from Hell**, который оценивает, сколько времени
ещё можно выжать из уровня, и после финиша показывает, где именно вы его
потеряли.

Работает через Harmony-патчи поверх оригинальной `Assembly-CSharp.dll` —
подменять файлы игры не нужно. Ничего не отправляет и в игровой процесс не
вмешивается: только читает реплеи топа и сам уровень.

## Что показывает

### На экране прицеливания — два лимита

Плагин скачивает реплеи топ-5 текущей таблицы (уровень + мутатор) и выводит в
углу:

```
WR 2.485 (faustian bargain)   Лимит A 2.447 (-38 мс)   топ-5, точек 13, склеек 1
  0.000–0.629: этот отрезок как у #4 Pr0XeLa, на нём быстрее WR на 38 мс
Лимит B 2.430 (-55 мс): разгон на земле −0 мс, рор −0 мс, телепорт −55 мс (2), срезы −0 мс (0)
```

**Лимит A — лучшее, что складывается из уже сыгранного.** Трасса WR режется
контрольными точками через каждые 10 тиков, и забег можно «пересесть» с одного
игрока на другого только там, где они были в одном состоянии: рядом (до 0.75 м),
с той же скоростью по горизонтали и по вертикали отдельно, с тем же числом
зажжённых свечек и подборов, и когда ничего не летит — ни шар телепорта, ни
огненный шар к свечке (иначе склейка присвоила бы себе чужой бросок). Если
следующий игрок в точке склейки стоит впереди, эта фора вычитается. Каждый кусок
лимита A кто-то реально сыграл.

**Лимит B — сколько ещё можно выжать на линии самого WR.** Считается из
физики игры, прочитанной из её кода:

| Часть | Как считается |
|---|---|
| Разгон на земле | «Идеальная» скорость не ниже реальной, разгоняется не быстрее 60 м/с² до 12.18 и платит за повороты так же, как контроллер персонажа |
| Воздух | Не засчитывается: время полёта задаёт гравитация, а не горизонтальная скорость. Набранная в воздухе скорость переносится на землю после приземления |
| Рор | Держать без провалов: рост +5 м/с за тик до 70, перенажатие без потерь; вынужденные паузы WR (заряды кончились, стрельба по свечкам) повторяются как есть |
| Телепорт | Бег в сторону шара, пока он летит: игрока переносит в ближайшую к нему точку пути шара, так что каждый метр вдоль пути укорачивает полёт после телепорта. Разбег обрезается стенами и опасными объектами |
| Срезы | Прямой путь к дальней точке траектории, если капсула игрока проходит его по полу, не задевая стен и ничего с `canKill` |

Время ожидания (пока летит шар, перед броском, перед свечкой) лимит B не
трогает — там решает момент броска, а не скорость бега.

### После финиша — разбор вашего забега

На экране победы:

```
Ваш забег 5.967   WR 5.907 (faustian bargain), вы +60 мс
Лимит A для вас: 5.778 (−189 мс)
  где теряете к лимиту (время по вашему забегу):
    1.667–3.167: −81 мс, лучше у #4 ssolle
    4.333–5.167: −49 мс, лучше у #1 faustian bargain
    5.167–5.500: −25 мс, лучше у #2 NatiaRone
    ещё 34 мс мелкими кусками по забегу
На вашей линии (B): …: разгон на земле −…, рор −…, телепорт −…, срезы −… мс
```

Это лимит A, где основой взят **ваш** забег: на каждом отрезке ваше время против
лучшего куска топ-5, начатого из того же состояния. Отрезки меньше 2 мс в список
не попадают. Разбору нужен загруженный топ этой таблицы — он скачивается на
экране прицеливания; последние разборы сохраняются в
`BepInEx/cache/SeumLimit/reviews`.

## Что лимиты не умеют

* **Эдж, баунс, стрейфы** — это артефакты столкновений `CharacterController`, в
  коде игры их нет, поэтому вывести их из формул нельзя. Лимит A их учитывает,
  если кто-то из топ-5 сделал это лучше в том же месте; лимит B — нет.
* **Момент броска и прицел** телепорта, ожидание перед свечками — берутся как у
  WR.
* **Движущиеся платформы и двери** для срезов берутся в том положении, в каком
  они на экране прицеливания (обычно закрыты) — срезов меньше, а не больше.

## Особенности реплеев, которые пришлось учесть

* Время событий в реплее отсчитывается от рестарта, а кадры — от первого
  нажатия; между ними `waitTime`.
* Действие, которым начат забег (бросок, рор), в реплей не попадает: запись
  включается на тик позже. Плагин восстанавливает его по траектории.
* Телепорт в реплее — только скачок позиции, отдельного события нет.
* Время на лидерборде дробнее тика: игра добавляет долю последнего тика до
  ворот выхода.

## Кэш

`BepInEx/cache/SeumLimit`:

| Папка | Что | Сколько хранится |
|---|---|---|
| `results` | готовые лимиты по таблицам; пересчитываются, когда меняется WR | результаты старых версий анализа удаляются при запуске |
| `reviews` | разборы ваших забегов | последние `KeepReviews` (50) |
| `dump`, `live`, `runs` | диагностика, только если включена | — |

## Конфиг

`BepInEx/config/SeumLimit.cfg`, создаётся при первом запуске.

<details>
<summary>Пример конфига (SeumLimit.cfg) со всеми параметрами</summary>

```ini
[01 - General]

## Master switch.
Enabled = true

## How many of the top runs to download and splice together for the limit.
# Acceptable value range: From 1 to 15
TopCount = 5

## Show the limit in the corner of the aim screen.
ShowOverlay = true

## How many run reviews to keep in BepInEx/cache/SeumLimit/reviews; older ones are deleted at startup. 0 stops saving them (the review is still shown).
# Acceptable value range: From 0 to 10000
KeepReviews = 50

[02 - Diagnostics]

## Record every run you play, tick by tick, with inputs and the character's internal state, to BepInEx/cache/SeumLimit/live. For working on the powerup models only: it writes a few hundred KB per attempt, restarts included.
RecordLive = false

## Also save the downloaded top runs as CSV under BepInEx/cache/SeumLimit/runs, for working on the analysis outside the game.
SaveRunCsv = false

## Writes a diagnostic dump to BepInEx/cache/SeumLimit/dump: the physics step, the character's movement settings, the level's colliders grouped by how they are marked, and - if a replay is loaded - that replay as CSV. Press it on a level, and again while a leaderboard replay is playing.
DumpKey = F7
```

</details>

С [SeumReplay](../SeumReplay/README.md) реплеи топа берутся из его дискового
кэша — открытие экрана прицеливания почти мгновенное.
