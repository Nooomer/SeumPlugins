# SeumReplay

Плагин для **SEUM: Speedrunners from Hell**, чинящий и ускоряющий загрузку
реплеев с лидербордов.

Работает через Harmony-патчи поверх оригинальной `Assembly-CSharp.dll` —
подменять файлы игры не нужно.

## Совместимость: запись реплеев не трогается

Плагин патчит **только чтение**: распаковку, скачивание и воспроизведение.
`Replay.record`, `Replay.packageReplay` и `Replay.replaySummary` остаются ровно
такими, какими их выпустила игра, потому что их результат уходит в Steam-лидерборд
и его должны уметь прочитать **все** — в том числе игроки без модов. Реплей,
записанный с этим плагином, побайтово совпадает с реплеем, записанным без него.

## Главное: баг в распаковщике игры

`Replay.unpackReplay` держит кадры, события и данные снарядов в списках массивов
по 60 / 100 / 20 элементов. Длину **последнего** блока он берёт как
`count % chunkSize`:

```csharp
int num3 = ((i == num2 - 1) ? (replaySession.frameCount % 60) : 60);
```

Когда `count` делится на размер блока нацело, остаток равен **нулю**, а не
размеру блока. Целый блок записей не читается, поток остаётся сдвинутым на
`60 × 24 = 1440` байт — и всё, что идёт дальше (счётчик событий, сами события,
счётчик снарядов), читается не с того места.

Формат при этом плоский: `packageReplay` пишет ровно `frameCount` кадров подряд,
блоки по 60 существуют только в памяти. То есть на диске и в Steam всё лежит
корректно, ломается именно чтение.

Что из этого следует на практике (проверено сравнением двух распаковщиков на
одинаковых блобах, тесты воспроизводимы — см. «Проверка» ниже):

| Случай | Что делает ванильный распаковщик |
|---|---|
| `frameCount % 60 == 0` | `EndOfStreamException` внутри Steam-колбэка. Исключение вылетает **до** строки `finished = true`, запрос навсегда зависает в списке бэкенда, а экран реплея остаётся на «Loading…» до выхода из него. |
| `eventCount % 100 == 0` | Последние 100 событий читаются нулями, счётчик снарядов берётся из середины блока событий — данные снарядов теряются целиком. |
| `projectileDataCount % 20 == 0` | Последние 20 записей о снарядах теряются: выстрелы в конце забега летят не туда, куда летели на самом деле. |

Счётчик кадров — это число физических шагов забега, так что «неудачные» значения
попадаются регулярно, а не в теории.

`FixChunkTails` (по умолчанию включено) заменяет распаковщик на реализацию,
которая идёт по записям, а не по блокам, — граничный случай исчезает как класс.
Заодно она читает байты напрямую из массива вместо `BinaryReader` поверх
`MemoryStream` (примерно вдвое быстрее) и, при `TolerateTruncated`, на
повреждённом блобе обрезает счётчики по фактическому размеру данных и играет то,
что доехало, вместо исключения.

## Остальное

### Загрузка

| Настройка | Что делает |
|---|---|
| `DiskCache` | Скачанные реплеи складываются в `BepInEx/cache/SeumReplay` под именем Steam UGC-хэндла. Повторный просмотр того же реплея — чтение файла вместо запроса в Steam. Ключ безопасен: новый личный рекорд публикуется как **новый** UGC-файл, и строка лидерборда начинает указывать на новый хэндл, так что устаревший забег из кэша прийти не может. Игра кэширует распакованную сессию на объекте `Score`, но строки лидерборда пересобираются при каждом обновлении, поэтому без диска один и тот же WR качается заново каждый раз. |
| `CacheBudgetMegabytes`, `CacheMaxAgeDays` | Потолок кэша (по умолчанию 64 МБ) и срок жизни файла (60 дней). Вытесняются самые давно не открывавшиеся. |
| `DownloadTimeout` | Сколько ждать UGC-загрузку до отмены и повторной попытки. В ванили — **3 секунды**: на медленном канале каждая попытка убивается ровно перед тем, как долететь. По умолчанию 10. |
| `DownloadRetries` | Сколько раз повторять (в ванили 5). После исчерпания попыток ваниль просто молча перестаёт что-либо делать. |
| `PrefetchCount` | Пока игрок стоит на экране прицеливания и реплеи для уровня уже открыты, начать качать N лучших забегов — открытие реплея становится мгновенным. 0 выключает. |

Плюс переписанный колбэк `DownloadReplayRequest.replayDownloaded`: он выставляет
`finished` в `finally`, так что зависших запросов не остаётся ни при каком
исходе, различает «Steam вернул ошибку», «Steam вернул пусто», «блоб не
распаковался», и по дороге кладёт сырые байты в кэш (только если они
распаковались целиком — битая загрузка не превращается в вечно битый кэш).

### Экран реплея

`StatusOverlay` дописывает под «Loading…» строку о том, что происходит на самом
деле: процент загрузки (из `GetUGCDownloadProgress`), сколько уже идёт, какая это
попытка, а если Steam сдался — почему и какой клавишей повторить. Во время
воспроизведения та же строка показывает позицию и скорость.

### Управление воспроизведением

`PlaybackHotkeys` (по умолчанию включено):

| Клавиша | Действие |
|---|---|
| `Space` | Пауза / продолжить |
| `[` / `]` | Скорость вдвое ниже / выше (0.05x … 4x — потолок ванильного ползунка) |
| `.` | На паузе — шаг на один записанный кадр |
| `Home` | Перезапустить реплей с начала; если реплей не загрузился — повторить загрузку. Не `R` намеренно: ванильное действие «рестарт» читается в `Hud.Update` без проверки состояния, так что `R` во время реплея и так выкидывает на экран прицеливания |

## Проверка

Правка распаковщика проверялась вне игры: синтетическая сессия упаковывается
байт-в-байт как это делает `Replay.packageReplay` (включая `GetBuffer()` с
хвостом ёмкости), а затем распаковывается обеими реализациями — ванильной
(построчная копия IL из игры) и новой.

```
  PASS  odd sizes: SeumReplay decoder
    stock decoder on the same blob: identical
  PASS  frames on a chunk boundary: SeumReplay decoder
    stock decoder on the same blob: threw EndOfStreamException
  PASS  events on a chunk boundary: SeumReplay decoder
    stock decoder on the same blob: projectileDataCount 0 != 7
  PASS  projectile data on a chunk boundary: SeumReplay decoder
    stock decoder on the same blob: projectile entry 1 differs
  PASS  everything on a chunk boundary: SeumReplay decoder
    stock decoder on the same blob: threw EndOfStreamException
  PASS  empty replay: SeumReplay decoder
    stock decoder on the same blob: identical
  PASS  truncated blob decodes to a shorter replay instead of throwing
  PASS  unknown version is rejected

  18001 frames / 524288 B: SeumReplay 0,51 ms, stock 0,96 ms (1,9x)
```

## Конфиг

`BepInEx/config/SeumReplay.cfg`, создаётся автоматически при первом запуске
плагина. `Enabled = false` отключает все патчи целиком. `DownloadTimeout` и
`DownloadRetries` читаются один раз при старте (они вшиваются в код
транспайлером), остальное применяется на лету.

<details>
<summary>Пример конфига (SeumReplay.cfg) со всеми параметрами</summary>

```ini
[01 - General]

## Общий выключатель. При false не применяется ни один патч.
Enabled = true

[02 - Decoding]

## Ванильный распаковщик считает размер последнего блока как
## count % chunkSize (60 кадров, 100 событий, 20 записей снарядов), так что
## при количестве, кратном размеру блока, этот блок читается как пустой, а
## все дальнейшие поля — не с того места. Обычная причина реплея, который
## либо навсегда зависает на «Loading...», либо проигрывается с мусором.
FixChunkTails = true

## Если блоб реплея короче, чем заявлено в его заголовке, обрезать счётчики
## по фактическому размеру и проиграть то, что доехало, вместо исключения.
TolerateTruncated = true

[03 - Download]

## Хранить скачанные реплеи в BepInEx/cache/SeumReplay по хэндлу Steam UGC.
## Повторное открытие того же реплея — чтение файла вместо похода в Steam.
DiskCache = true

## Потолок дискового кэша реплеев в мегабайтах. Старые файлы вытесняются
## первыми.
# Допустимые значения: 1-4096
CacheBudgetMegabytes = 64

## Реплеи, к которым не обращались столько дней, удаляются при старте.
## 0 отключает проверку возраста, оставляя только лимит по размеру.
# Допустимые значения: 0-3650
CacheMaxAgeDays = 60

## Сколько секунд ждать загрузку реплея из Steam, прежде чем повторить
## попытку. В ванили — 3 секунды, чего мало на медленном канале.
# Допустимые значения: 1-120
DownloadTimeout = 10

## Сколько раз повторять зависшую загрузку.
# Допустимые значения: 0-50
DownloadRetries = 5

## Пока открыт экран лидерборда уровня, заранее скачивать топ-N забегов,
## чтобы их открытие было мгновенным. 0 отключает предзагрузку.
# Допустимые значения: 0-15
PrefetchCount = 1

[04 - Interface]

## Показывать вместо немого «Loading...» реальный статус: процент загрузки,
## номер попытки, причину ошибки. Во время воспроизведения та же строка
## показывает позицию и скорость.
StatusOverlay = true

[05 - Playback]

## Управление воспроизведением реплея с клавиатуры, поверх штатного ползунка
## скорости.
PlaybackHotkeys = true

## Пауза / продолжить воспроизведение.
PauseKey = Space

## Замедлить воспроизведение вдвое (до 0.05x).
SlowerKey = LeftBracket

## Ускорить воспроизведение вдвое (до 4x — потолок штатного ползунка).
FasterKey = RightBracket

## На паузе — шаг на один записанный кадр.
StepKey = Period

## Перезапустить реплей с начала; если реплей не загрузился — повторить
## загрузку. Не R: штатное действие рестарта в игре читается без проверки
## состояния, поэтому R во время реплея и так выкидывает на экран прицеливания.
RestartKey = Home

[06 - Diagnostics]

## Логировать каждую распаковку и попадание в кэш с размерами и временем.
VerboseLogging = false
```

</details>
